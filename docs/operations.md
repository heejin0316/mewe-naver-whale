# ME:WE 공유 데이터 운영 절차

문의 창구: h33jin.jeong@gmail.com. 이 절차는 운영자가 직접 수행하는 준비안이며 자동화가 설정된 상태가 아닙니다. Firebase Spark를 유지하고 Cloud Functions·Storage 업로드·유료 TTL은 사용하지 않습니다.

## 삭제 및 처리 정지 요청

1. 이메일로 요청을 받고 목적과 대상 범위를 확인합니다. 공유 코드 등은 비공개로 다루고 비밀번호·인증 토큰은 요청하지 않습니다.
2. 익명 계정은 이메일과 연결되지 않습니다. 코드 소지만으로 작성자임을 입증할 수 없습니다. 작성자 인증 기능이 준비되기 전에는 소유권이 불명확한 요청을 임의 삭제하지 말고 증빙·내용·안전상 필요를 검토합니다.
3. 권한이 확인되면 Firestore `shares/{정규화된 코드}`의 대상만 삭제합니다. 계정 삭제 요청은 필요한 공유 문서 처리 후 Authentication의 해당 UID를 별도로 삭제합니다. 처리 전에 대상과 범위를 재확인합니다.
4. 삭제한 코드는 수신할 수 없는지 확인합니다. 이미 받은 사람의 로컬 복사본은 회수하지 못한다는 점을 안내합니다.
5. 완료 시각과 최소한의 처리 결과를 기록합니다. 메일과 처리 기록의 보관 기간은 공개 전 확정합니다. 인증 토큰·원본 페이지 목록을 처리 기록에 남기지 않습니다.

## 만료 문서 정리

현재 Firestore 규칙은 만료 후 조회를 차단하지만 문서를 삭제하지 않습니다. `expiresAt`을 확인해 대상 문서를 정리하는 담당자·주기·최대 보관 기간을 확정해야 합니다. 아직 ‘매일 삭제’나 ‘7일 후 자동 삭제’라고 약속하지 않습니다. 실제 운영 방침을 확정하면 개인정보 문구도 갱신합니다.

익명 계정은 공유 문서와 별도로 남습니다. 남아 있는 문서 소유권을 고려한 계정 정리 정책이 필요합니다. 단순히 오래된 사용자라는 이유로 무조건 삭제하지 않습니다.

## 악용 및 콘텐츠 신고

불법·피싱·개인정보 노출 신고를 이메일로 접수합니다. 필요한 공유 문서를 확인하고 접근 중단·삭제를 판단합니다. 공개 피드는 없지만 코드로 사용자 자료를 전달하는 기능이므로 신고와 운영 조치가 필요합니다. 실효성 있는 차단과 남용 방지는 추가 검토 항목입니다.

## 서비스 장애와 무료 한도

Firebase 콘솔에서 사용량과 인증·규칙 오류를 확인합니다. 자료 삭제나 규칙 전체 허용으로 오류를 우회하지 않습니다. 공개 조회·쓰기 허용 규칙을 적용하지 않습니다. 한도 소진 시 공유가 일시 실패할 수 있고 로컬 작업공간은 유지됩니다. 과금 플랜 변경은 사용자의 별도 결정 사항입니다.
