## 삭제 및 처리 정지 요청

1. 이메일로 요청을 받고 목적과 대상 범위를 확인합니다. 공유 코드 등은 비공개로 다루고 비밀번호·인증 토큰은 요청하지 않습니다.
2. 익명 계정은 이메일과 연결되지 않습니다. 코드·UID 소지만으로 작성자임을 입증할 수 없습니다. 공유 시점, 요청 대상에 포함된 본인 정보와의 관계 등 최소 자료를 검토합니다. 단순 코드 소지만으로 다른 사람의 자료나 계정을 삭제하지 않습니다. 소유권 확인이 안 되면 추가 확인 방법과 보류 이유를 안내합니다. 개인정보 노출 신고는 작성자 여부와 별개로 신고자의 정보와 피해를 확인하여 접근 중단 여부를 검토합니다. 비밀번호·인증 토큰·계정 전체 화면은 요구하지 않습니다.
3. 권한이 확인되면 Firestore `shares/{정규화된 코드}`의 대상만 삭제합니다. 계정 삭제 요청은 필요한 공유 문서 처리 후 Authentication의 해당 UID를 별도로 삭제합니다. 처리 전에 대상과 범위를 재확인합니다.
4. 삭제한 코드는 수신할 수 없는지 확인합니다. 이미 받은 사람의 로컬 복사본은 회수하지 못한다는 점을 안내합니다.
5. 완료 시각과 최소한의 처리 결과를 기록합니다. 메일과 개인정보가 포함된 처리 기록은 완료 후 30일 이내 삭제합니다. 인증 토큰·원본 페이지 목록을 처리 기록에 남기지 않습니다.

## 만료 문서 정리

현재 Firestore 규칙은 만료 후 조회를 차단하지만 문서를 삭제하지 않습니다. 담당자가 매주 아래 순서로 처리합니다. ‘만료 즉시 자동 삭제’라고 안내하지 않습니다.

1. Firebase 콘솔에서 `mewe-naver-whale`의 Firestore `(default)` → `shares` 컬렉션을 엽니다.
2. `expiresAt`이 현재 시각 이전인 문서를 확인합니다. 별도로 `createdAt`이 현재 시각에서 14일 이전인 문서가 남아 있지 않은지도 확인합니다.
3. 시간대와 필드 타입(timestamp), 대상 코드, 만료 여부를 확인한 후 해당 문서만 삭제합니다. 컬렉션 전체나 아직 유효한 문서를 일괄 삭제하지 않습니다.
4. 삭제 후 해당 코드로 목록을 받을 수 없는지 확인합니다. 처리 일시·삭제 건수만 기록하고 개인 URL·코드 원문을 기록에 복사하지 않습니다.
5. 생성 후 14일이 지난 자료가 0건인지 재확인합니다. 주간 작업을 놓치지 않도록 운영자가 일정을 관리합니다. 이번 코드 작업으로 서버 자동 삭제나 예약 작업이 생성되지는 않았습니다.

익명 계정은 공유 문서와 별도로 남습니다. 이용 종료·삭제·동의 철회 요청의 대상 UID와 본인 관계를 확인한 뒤 필요한 공유 문서 처리 후 Authentication 사용자 항목에서 해당 계정을 삭제합니다. 계정 삭제만으로 Firestore 문서가 사라지지 않으므로 두 항목을 각각 확인합니다. 단순히 오래된 사용자라는 이유로 무조건 삭제하지 않습니다. Google의 인증 로그·백업 제거 기간은 운영 문서 삭제 기한과 구분합니다.
