# ME:WE 심사 설명 및 시험 방법

대상: 0.3.0. 운영팀 ewhale · 개발자 정희진. 현재 문서는 제출 준비본입니다. 운영 Firebase 최종 검증과 개인정보 미결 항목을 완료한 뒤 심사 자료로 사용합니다.

## 핵심 기능

사용자가 선택한 학습 페이지를 기기에 저장하고 다시 여는 사이드바 앱입니다. 네이티브 듀얼탭 구성을 보존하고, 사용자가 요청할 때 웹페이지 목록을 짧은 코드로 공유합니다. 페이지 본문을 삽입·수정하는 콘텐츠 스크립트와 외부 실행 코드가 없습니다.

## 권한과 사용 범위

| 권한 | 실제 사용 |
| --- | --- |
| storage | 작업공간·순서·인증 정보의 로컬 저장, 실행 탭과 수신 미리보기의 세션 저장 |
| tabs | 현재 페이지 제목·URL 읽기, 페이지 생성·이동·닫기, 실행 탭 ID 확인 |
| debugger | getTargets로 일반 조회에서 누락된 듀얼탭의 탭 ID 확인. attach·sendCommand 미사용 |
| clipboardWrite | 사용자가 누른 공유 코드 복사 처리 |
| identitytoolkit.googleapis.com | Firebase 익명 인증 |
| securetoken.googleapis.com | 인증 토큰 갱신 |
| firestore.googleapis.com | 공유 문서 생성과 코드별 조회 |

디버거 권한은 개발 중 제거하지 못한 잔여 권한이 아니라 듀얼탭 확인을 위한 현재 구현의 의존성입니다. ID를 확인한 뒤 탭 API로 페이지를 조회합니다. 다른 페이지를 디버깅하거나 명령을 보내지 않습니다. 최소 권한 대안과 선택 권한 전환 가능성은 제출 전 검토 항목입니다.

## 심사자가 따라 할 순서

1. 새 웨일 프로필에 패키지를 설치하고 사이드바에서 ME:WE를 엽니다. 별도 앱이나 사용자 Firebase 설정은 필요하지 않습니다.
2. 일반 웹페이지 3개를 열고 그중 2개를 듀얼탭으로 구성합니다. ‘지금 작업공간 저장’에 각각의 페이지와 A/B 표시가 나오는지 확인합니다.
3. 이름을 넣어 저장하고 카드의 열기로 복원합니다. 닫기를 눌러 앱으로 연 탭만 닫히고 기존 탭은 남는지 확인합니다.
4. 카드 메뉴에서 수정하고 페이지 하나를 제거해 저장합니다. 드래그로 순서를 바꿉니다. 6번째 작업공간도 저장할 수 있습니다.
5. 공개 웹페이지로 구성한 카드의 공유 버튼을 눌러 목록을 확인하고 코드를 복사합니다. 실제 개인 자료나 비공개 URL을 사용하지 않습니다.
6. 다른 프로필의 ‘공유 작업공간 받기’에 방금 만든 코드를 입력해 미리보기 후 저장 또는 바로 열기를 확인합니다. 심사용 고정 코드는 만료되므로 제공하지 않습니다.
7. 테스트 PDF를 브라우저로 열어 저장하고, 공유 미리보기에서 해당 파일이 제외되는지 확인합니다. 경로만 저장되며 파일 업로드는 없습니다.
8. 앱 정보에서 문의 주소와 개인정보 안내를 확인합니다. 인터넷 연결 실패 시 공유 오류를 안내하고 로컬 작업공간은 유지되는지 확인합니다.

## 2026-10-12 제출 전 검토

판정: **현재 상태로 심사 요청은 보류 권장**. 아래 기능 시험은 통과했지만 개인정보·공유 운영 및 제출 이미지 준비가 남아 있습니다. 검토 대상은 커밋되지 않은 UI 변경을 포함한 로컬 0.3.0입니다. 테스트가 심사 승인이나 모든 환경에서의 정상 작동을 보장하지는 않습니다.

### 제출 전 해결할 항목

1. **개인정보 처리방침 확정·공개** — `shared/privacy-content.js`에 초안 표시, 실제 Firestore 위치·최대 보관 기간·삭제 주기·시행일 미확정 문구가 남아 있습니다. 공유 문서뿐 아니라 익명 계정과 문의 메일도 포함해 실제 운영 방침을 정해야 합니다. 예정 공개 URL은 이번 환경에서 접근 여부를 확인하지 못했습니다. 도구 접근 실패와 로컬 네트워크 제한이 있었으며, 이를 404나 미배포의 증거로 해석하지 않습니다.
2. **공유받기 전 인증 처리 안내** — `features/sharing/view.js`의 받기 화면은 코드 입력과 확인 버튼만 표시하지만, `firebase.js`의 `get()`은 익명 계정 생성/인증을 수행합니다. 받기에서도 네트워크 요청 전에 처리 내용과 정책을 확인하고 동의할 수 있게 보완해야 합니다. 공유 생성 화면의 안내 역시 확정 정책과 맞춰야 합니다.
3. **삭제·처리 정지 요청 실행 수단** — `docs/operations.md`는 준비안입니다. 익명 UID가 이메일과 연결되지 않으므로 코드나 이메일만으로 작성자를 확인할 수 없습니다. 실제 작성자 확인·삭제 절차와 만료 자료 정리 담당자·주기를 정하고 실행 검증해야 합니다. 앱 내 삭제 버튼이 일률적으로 필수라는 의미는 아닙니다. 신고 접수 후 차단·삭제 및 공유 남용 대응도 검토가 필요합니다.
4. **운영 서비스 최종 시험** — 운영 Firebase에 게시된 규칙·익명 인증·저장 위치는 이번 로컬 시험으로 확인되지 않습니다. 실제 두 사용자로 생성·받기·저장·열기를 검증하고, 브라우저 재시작/업데이트 데이터 유지 및 사용자가 보고한 실제 사이드바 토글 문제도 최종 설치본에서 재확인해야 합니다.
5. **제출용 이미지 준비 완료 (검토 후 반영)** — 아이콘은 실제 128×128 PNG입니다. `docs/images`는 소개용이며, 별도로 `delivery/screenshots`에 1280×800 PNG 2장을 실제 웨일 확장앱 UI와 예시 데이터로 촬영·검수했습니다. 개인정보/UI 보완 시 재생성해야 합니다.

### 보완 권장 사항

- `debugger`는 실제로 `getTargets`에만 사용하고 attach/sendCommand는 사용하지 않습니다. 심사 설명에 필요성을 구체적으로 유지하고 더 작은 권한 대안 여부를 점검하세요. 권한 이름만으로 반려를 단정하지 않습니다.
- 주요 버튼의 흰 글자와 그라데이션 색상 대비는 색상 지점별 약 1.63:1, 2.75:1, 3.35:1입니다. 작은 흰 글자가 흐려질 수 있으므로 버튼용 그라데이션을 더 어둡게 하거나 글자색을 조정하는 것을 권장합니다. 이번 검토에서 디자인을 임의 변경하지 않았습니다.
- 전달 후보는 최근 UI 변경과 포장 도구·이미지를 함께 한국어 커밋으로 기록합니다. 향후 보완 사항도 동일하게 검증본과 제출물을 일치시키세요.
